# Agent Note: keyboard shortcuts in the Web client

Status: implemented

[English](2026-08-13-client-keyboard-shortcuts.md) | 中文

## Problem

Web 界面上最高频的两个操作——打开 Settings 与新建 Session——各自只有侧边栏列里的一个控件可达。两者都是人在两轮之间、手已经放在键盘上时会做的事，而它们都没有组合键。桌面外壳无法提供：它的窗口把 harness 界面当作不带 preload 的普通网页内容加载，因此那里的菜单加速键只会拿走这个键，却无处可送（见[桌面应用 Note](../architecture/2026-08-13-electron-desktop-application.md)）。

## Decision

组合键放在客户端，放在已经持有该操作的那个组件上。`SettingsRoot` 把 `⌘,` / `Ctrl+,` 绑到它自己的 `open` 状态，`SidebarRoot` 把 `⌘K` / `Ctrl+K` 绑到它本就为之渲染了两个按钮的 `startSession` 回调、把 `⌘B` / `Ctrl+B` 绑到 `toggleSidebar`，`WorkspaceBrowser` 把 `⌘O` / `Ctrl+O` 绑到其区头按钮背后的添加工作区状态、把 `⇧⌘F` / `Ctrl+Shift+F` 绑到它的搜索。没有任何状态被上提：操作的持有者就是其快捷键的持有者，因此组合键不会比旁边的控件活得更久，也不会与它相矛盾。

组合键继承的不只是控件的动作，还有它的可用性。添加按钮只在当前界面的目录流 slot 被占用时渲染，因此 `⌘O` 读取同一份占用状态：slot 为空时按下不做任何事，而不是预置一个 picker 状态，让稍后挂载的占用方在没有任何手势的情况下把它拉起来。

当一个控件的两种列状态以不同路径抵达该操作时，组合键分别走每种状态自己的路径，而不是另造第三条。`⌘B` 是切换而非收起，因为轨道没有第二个键可以用来回来，而它下面的按钮在两种状态下本就是同一个。搜索组合键在展开的列里直接显示搜索框，从轨道按下时则预置焦点并请求外壳展开——也就是轨道自身控件的做法，因为搜索框只存在于展开的列中。

`dsh-client-ui-primitives` 中的 `useShortcut` 是它们共享的唯一一块。它绑定一个 document 级组合键，并持有平台选择：Apple 平台用 Command，其他平台一律用 Control，从 user agent 读出。接受任意一个修饰键会更简单，但那是错的——macOS 把 Control+字母交给每一个输入框里的文本编辑（`Ctrl+K` 删除到行尾），而 Windows 把 Meta+字母交给桌面外壳。一个组合键要么是裸键，要么是 `{ key, shift }`，而 Shift 在两个方向上都属于它的身份：需要 Shift 的组合键在没有 Shift 时不应答，不需要 Shift 的组合键在按住 Shift 时也不应答。该钩子会拒绝携带另一平台修饰键的按下、Alt（macOS 用它组合字符）、组合键并未要求的 Shift，以及按住不放产生的重复；它调用 `preventDefault`，使浏览器不再对该键动作，并通过 ref 读取操作，因此调用方无需 `useCallback`。

组合键在焦点所在的任何位置都生效，包括输入框，因为带修饰键就意味着这次按键从来不是用户想输入的文本。`⌘K` 与 `⌘B` 在侧边栏的两种状态下都生效，因为它们属于这一列而不属于其中任何一个按钮；`⌘O` 与 `⇧⌘F` 同样如此，因为浏览区在两种状态下都填满这一列。面板已打开时按 `⌘,` 会让它保持打开，并停留在当前分区。

每个控件都在悬停与键盘聚焦时标示自己的组合键，经由 `shortcutLabel`——平台判定的另一半，它写出 `⌘K` 或 `Ctrl+K`。New Session 的 tooltip 内容是 `New session ⌘K`，并且现在在两种列状态下都出现，而不再只在轨道状态，因为组合键正是展开后按钮自带标签所没有的那一项。添加工作区、搜索与收起按钮本来就有标示各自动作的 tooltip，因此各自在其后追加组合键——`添加工作区 ⌘O`、`搜索 ⇧⌘F`、`收起侧边栏 ⌘B`（该按钮的两种标签下都是如此）——而可访问名称仍只保留动作本身。此前完全没有 tooltip 的设置触发控件，则只显示组合键本身：那个外壳是不持有任何文案的组合面，而 slot 系统的 `label` 选项——导航行承载注册方文字的方式——只存在于 list 类型的 slot 上，而 `settings.trigger` 是 single。

由于桌面外壳的菜单会在页面看到之前拿走它所占用的任何加速键，这些组合键是两层之间的契约，而不是客户端本地的选择。桌面菜单测试持有这五个键，并拒绝任何要占用它们的菜单项。它也正是抓住 `⇧⌘O` 的那一道：那本是添加工作区最顺手的组合键，但外壳自己的「在浏览器中打开」已经占着它。

## Alternatives considered

- **由桌面菜单项驱动页面。** macOS 惯例把 Settings 放在应用菜单的 `⌘,` 下，而菜单是用户唯一读得到的那份键盘映射。它需要一条从外壳进入 harness 界面的通路——桌面 Note 已基于沙箱理由否决的 preload，或者对页面必须暴露的某个钩子执行 `executeJavaScript`。两者都会让外壳参与它本来一无所知的界面操作，且都到不了浏览器里的 `dsh web`，而同样的组合键在那里也必须可用。
- **在客户端做一个快捷键注册表服务。** 由一个插件持有键位映射，能给客户端带来 `menu.ts` 给外壳带来的东西：一份可读的映射加冲突检测。但它同时要求把每个操作从其持有组件中上提——尤其是设置面板的 `open` 状态——而 `⌘O` 的加入并不需要这一步：第三个组合键只是在第三个包里重复了同样的一行写法，没有与任何键冲突。注册表能回答的是当前设计回答不了的问题：两个客户端包是否占用了同一个键；而今天只有逐个比对四个文件的读者才看得出来。这个问题里「客户端对外壳」的那一半是有覆盖的——桌面菜单测试抓住了 `⇧⌘O` 与「在浏览器中打开」的冲突——而它之所以有门禁，恰恰因为外壳那份映射是一个对象。客户端这份不是，下一个组合键就是继续为此付的账。
- **搜索用裸 `⌘F`。** 这是每个应用用来「在自身内查找」的组合键，而在浏览器标签页里它是读者的页内查找——页面最不该从他们手里拿走的那一个按键。`⇧⌘F` 才是编辑器放置「搜索自身内容」的位置，而 Shift 同时也把组合键抬离浏览器已经占据的那片空间。
- **只用 `metaKey || ctrlKey`，不读平台。** 代码少一半，也是 Web 应用里的常见做法。它会在 macOS 的输入框里对 `Ctrl+K` 触发，而那在该平台是一个文本编辑按键；并且它让这份映射的定义取决于用户碰巧按住了什么。
- **在设置 tooltip 里同样写出操作名。** 与 `New session ⌘K` 保持对称，代价是设置外壳唯一的那条规则：要么放宽 slot 选项，让 single slot 也能携带注册方的 `label` 供外壳解析，要么让外壳直接读取 `settings` 字典，从而成为触发 seat 已经渲染的那段文字的第二个来源。在不持有任何文字的前提下，那个外壳能说的就只有组合键本身。
- **改在布局外壳里绑定这些键。** 它们只有一个归处，而布局始终挂载。但它够不到这两个操作，除非从另外两个包穿进新的 props；而侧边栏列同样不是条件挂载的。

## Consequences

- 这些组合键在 `dsh web` 与桌面应用中来自同一份代码，浏览器自身菜单栏优先于页面的情形除外。在 macOS 上，Chrome 用自己的设置应答 `⌘,`，用打开文件对话框应答 `⌘O`，页面拿不到这两个键，因此它们只在桌面窗口里到达 harness 界面——那里没有任何东西占用它们。`⌘K`、`⌘B` 与 `⇧⌘F` 没有这样的竞争者。这种不对称是 macOS 独有的：菜单栏组合键在那里由应用解析，而 Windows 与 Linux 的浏览器把除一小撮保留键之外的按键都交给页面。
- 每个组合键都能从它作用的控件上被发现，而设置触发控件也得到了它此前从未有过的 tooltip——在收起后的轨道上，那也是这个按钮的第一条可访问提示，因为它的 seat 在那里只渲染图标、不渲染文字。
- 桌面外壳与客户端如今共享一份没有共同来源的键盘映射：客户端绑定 `,`、`k`、`o`、`b` 与 `Shift+f`，而桌面菜单测试重述这五者，以让外壳避开它们。新增客户端快捷键而不补上那条测试项，就可能在桌面端被无声遮蔽。
- `useShortcut` 增加了可选的 Shift，这是这份映射唯一需要的扩展：裸 `⌘`+字母几乎已被浏览器自己占尽，而 `⇧⌘` 大体仍是空的。Alt 仍被拒绝——macOS 用它组合字符。
- `useShortcut` 读取 `navigator.userAgent`。隐藏或伪装平台的浏览器会拿到 Control 拼法。
