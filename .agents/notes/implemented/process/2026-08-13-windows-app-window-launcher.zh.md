# Agent Note: Windows 启动器打开应用窗口而非复用标签页

Status: implemented

[English](2026-08-13-windows-app-window-launcher.md) | 中文

## 问题

[macOS 应用包](2026-08-13-macos-app-bundle-packaging.md)为 `dsh web` 提供了一个可双击的入口，其核心行为是标签页复用：重新触及该应用时，会把已显示该会话的浏览器标签页调至前台，而不是再开一个。Windows 上没有任何东西等价于使之成立的 AppleScript。那里没有手段枚举运行中浏览器的标签页：UI Automation 虽能遍历 Chromium 的可访问性树，却对版本与语言环境敏感；窗口标题匹配只有在目标标签页恰为活动标签时才找得到窗口；而 DevTools 协议要求以调试参数启动浏览器，无法施加于用户已经开着的会话。

## 决策

`scripts\windows\start-web.ps1` 通过「根本不产生标签页」来绕开复用问题。它向 Chromium 系浏览器申请一个独立窗口（`--app=<url>`），该窗口拥有自己的任务栏按钮，因此 Alt-Tab 可直接到达该会话，再次运行也会按标题将该窗口调至前台，而不是再开一个。所用浏览器在默认浏览器属于 Chromium 系时即为它，否则取已安装候选中的第一个；非 Chromium 的默认浏览器只会得到普通标签页且没有复用，启动器并不掩饰这一点。`pnpm run package:win` 在该启动器之上写出启动与停止两个快捷方式；打包是可选的，因为该启动器只是一个可从 checkout 直接运行的普通脚本。

窗口匹配采用对 `DeepSeek Harness` 的包含匹配——这是 `packages/client/web` 设置的标题中恒定的后缀。完整标题会在其之前带上会话名，因此相等匹配或前缀匹配将一无所获。

该启动器不像 macOS 应用包的 shim 那样常驻，因为 Windows 没有那个迫使进程常驻的启动签到机制。它以分离方式启动服务、等待 URL 行、打开窗口，然后退出；`-Stop` 则通过匹配 `node.exe` 进程命令行中的入口路径来结束服务。

## 验证状态

本次改动中的 PowerShell 从未被执行过。它是在 macOS 上编写的，而该机器上没有 PowerShell、wine、mono 或 .NET 运行时，连解析都做不到；其行为需要桌面会话与浏览器，而 CI 无法提供——仓库的[原生 Windows CI](2026-08-08-native-windows-pull-request-ci.md) 能构建并测试 harness，却无法驱动前台窗口。人工审查发现的问题本身即是风险的佐证：`Start-Process` 拼接参数数组时不加引号，因此含空格的 checkout 路径会破坏入口参数；`-like` 会把 Windows 路径中的反斜杠当作转义语法，因此进程匹配改用字符串包含；以及 `-WindowStyle` 无法与输出重定向共存。`-Check` 模式会一次性打印解析出的 Node 二进制、入口、服务状态、浏览器与窗口，且任何失败都会弹出对话框——因为从快捷方式启动的启动器两者皆无控制台可用。

## 曾考虑的替代方案

- **用 UI Automation 遍历浏览器标签页。** 这是 Windows 上实现真正标签页复用的唯一途径，其被否决的理由正是贯穿本记录的那一条：要确认其正确性就必须观察实时的可访问性树，而这在此处无法做到。交付未经测试的 UIA 遍历，只会产出在某个无人验证过的浏览器版本上悄然失效的代码。
- **对普通标签页做窗口标题匹配。** 廉价且现成，但它只有在目标标签页正好是活动标签时才能定位到浏览器窗口，因此恰恰在用户已经切走时退化为开出重复窗口——而那正是 macOS 那轮工作要消除的失败。
- **仿照 macOS shim 做一个常驻启动器。** shim 之所以存在，是因为在可执行文件向窗口服务器签到之前 LaunchServices 会一直弹跳 Dock 图标。Windows 没有这一要求，因此常驻进程一无所得，反而多出一个用户看不见也停不掉的进程。
- **做安装包（MSI、NSIS、Inno Setup）。** 否决，因为它回答的是另一个问题：安装包分发的是自包含程序，而这个启动器运行的是构建它的那台机器上的某个 checkout——与 macOS 应用包所受的限制相同。
- **复用 `.icns` 的图案。** macOS 图标位于 Big Sur 网格上，824 单位的方块周围留有透明边距，在任务栏上会显得明显偏小。Windows 变体填满画布，且多分辨率 `.ico` 被直接提交，因为打包步骤所在的机器上没有栅格化器。

## 后果

- Windows 上的第一次运行，就是这段代码的第一次执行。那里出现失败应视为预期成本而非意外，并且应当先看 `-Check`。
- Firefox 用户得到的是普通标签页且没有复用。要为他们实现复用，需要本次改动未提供的机制。
- 服务的存活时间长于窗口：关闭应用窗口并不会停止它，结束它要靠停止快捷方式或 `-Stop`。这与 macOS 不同——在那里退出应用包即停止服务。
- 两个脚本都没有门禁覆盖。它们是 PowerShell，因此仓库的 lint 与 typecheck 门禁完全看不见它们，这一点不同于 macOS 打包脚本。
